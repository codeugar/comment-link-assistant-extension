# 登录与 CAPTCHA 自动加入过滤列表 Spec

状态：Confirmed，可进入开发
基线：Comment Link Assistant v0.4.0

## 1. 背景

批量执行检测到目标网站需要登录或 CAPTCHA 时，当前会标记目标并跳过，继续执行下一个目标；同时也会把观察结果写入外链库。但该域名没有进入过滤列表，因此后续计划仍可能再次把同一域名加入执行队列。

## 2. 目标

1. 执行中确认目标需要登录或 CAPTCHA 时，继续保持“不暂停、标记当前目标、跳过并执行下一个”的现有行为。
2. 同时把目标的规范化域名自动加入现有过滤列表。
3. 后续批次以及当前批次内尚未执行的同域名目标，沿用现有过滤列表预检逻辑，直接标记为 `filtered`，不再打开页面。
4. 继续把 `loginRequired` / `captchaRequired` 观察结果写入外链库。

## 3. 数据规则

- 自动创建 `kind: domain` 的过滤条目，不创建精确 URL 条目。
- 域名使用过滤列表现有的 `normalizeFilterDomain` 规则：忽略协议、路径和 `www.`，并覆盖该域名及其子域名。
- 复用 `addFilterListEntryWithResult` 的并发串行化和去重能力；已有相同域名过滤条目时不重复创建。
- 不扩展 `FilterListEntry` 数据结构，本次不记录“登录”或“CAPTCHA”原因字段。
- 登录与 CAPTCHA 均命中同一域名时只保留一个域名过滤条目。

## 4. 触发范围

所有最终进入现有 `saveManualGate` 流程的场景都应触发自动过滤，包括：

- 页面分析确认需要登录或 CAPTCHA。
- 导航或同源重定向落到登录、注册、验证或 CAPTCHA 页面。
- 提交前准备阶段返回登录或 CAPTCHA。
- 点击提交后或提交结果验证阶段出现登录或 CAPTCHA；此时当前目标仍保持现有 `unconfirmed` 语义，但域名仍加入过滤列表。
- 外链库已知该域名需要登录或 CAPTCHA，队列预检直接跳过时。

不触发自动过滤：

- 普通网络错误、页面加载失败、找不到评论表单、表单校验错误、提交失败或结果未确认。
- 用户手动删除计划目标且未勾选“加入过滤列表”。

## 5. 失败与边界

- 写过滤列表是附加持久化操作，不得让批次暂停、失败或阻塞队列继续执行。
- 若过滤列表达到上限、存储写入失败或域名无法规范化：当前目标仍按登录/CAPTCHA 规则完成并继续下一个；外链库观察仍独立尝试。
- 自动过滤写入失败时不回滚已经完成的目标状态。
- 同一批次后续同域名目标会在下一次 runner step 的既有 `isTargetFiltered` 预检中变为 `filtered`。

## 6. 验收标准

- 首个 `https://www.example.com/post-a` 检测到登录后，过滤列表出现唯一的 `domain: example.com`。
- 当前批次后续 `https://blog.example.com/post-b` 在打开页面前被标记为 `filtered`。
- CAPTCHA 的行为与登录一致。
- 重复检测同一域名不会新增重复条目。
- 点击提交后才出现登录/CAPTCHA 时，当前目标保持原有 `unconfirmed` 状态，同时域名进入过滤列表。
- 自动写入过滤列表失败时，runner 仍继续下一个目标。
- 外链库的登录/CAPTCHA 标签仍正确更新。
- TypeScript、Biome lint、相关 Vitest 与生产构建通过。
